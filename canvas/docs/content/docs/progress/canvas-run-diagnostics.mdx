title: 托管任务故障排查
description: 部署任务诊断后定位视频参考上传和上游生成错误
---

后台菜单“画布任务”（`/admin/canvas-runs`）展示任务编号、用户、模型、状态、执行阶段、上游任务编号、错误及创建 / 更新时间。可搜索任务编号、用户邮箱 / ID、模型或上游编号，按执行中、成功和失败筛选。节点错误中的“任务”编号用于后台搜索，节点自身的 `video-...` ID 不是服务端任务编号。

任务阶段依次为：任务保存、参考素材转存、提交上游、等待上游结果、保存结果。任务诊断存入数据库，失败原因与退款在同一个事务提交；Redis 丢失或进程重启后仍可恢复。心跳续期失败、服务关闭和租约过期回收分别记录，不能把这些情况当作上游模型拒绝。

## 部署和验证

1. 按现有部署流程备份数据库。
2. 同时更新后端、宿主管理端与内嵌画布静态资源，确认启动迁移 `246_object_storage_assets.sql` 和 `247_canvas_run_diagnostics.sql` 成功。
3. 提交一个新任务。失败时从节点复制实际任务编号，在“画布任务”中检查阶段及错误；在“存储素材”中核对上传记录。
4. 必要时按 `run_id` 检索 `playground.video_reference_storage_started`、`_saved`、`_failed`、`_disabled`、`_no_inline` 和 `canvas run failed` 日志。

上传成功后还需检查同一任务的 `playground.video_reference_payload`。`stage=canvas_submit` 为画布提交给网关的参数数量，`stage=upstream_forward` 为网关向渠道转发前的参数数量；后者同时含所选 `account_id` 和映射后的 `model`。1 张图 + 原视频 + 深度视频应显示 `content_images=1`、`content_videos=2`、`content_audios=0`、`content_parts=4`（含文本）。这些日志只记录数量，不输出带签名的素材链接或提示词。若两处均为 1 图 + 2 视频，而渠道日志只有图片，继续检查渠道的二次转换和部署版本；上传记录中的数量不代表最终出口数量。

历史任务未保存的错误无法补回。重复查询原来的失败任务不会重新生成详情。回退应用代码可保留新增表、列和索引，无需删除任务与素材记录。

## 存储记录为空

启用对象存储但配置读取或客户端初始化失败时，任务停止并返回配置错误；明确关闭存储时沿用 inline 输入。素材已经是 HTTP(S) 或 asset 地址时不会重新上传。服务器在 Redis 任务保存阶段失败，也不会进入素材上传。

存储列表记录成功上传。上传前校验失败、配置异常或 PutObject 失败都没有成功记录；若文件上传成功但数据库记录写入失败，则明确提示“文件已上传，但素材记录写入失败”。因此列表为空不能单独证明具体失败阶段。

错误诊断不保存请求体、API Key、素材二进制或签名 URL。公网可达、Range 下载、上游多参考协议及深度 WebM 支持仍需在真实服务器验收。本地回归不等于已修复部署环境中的具体生成故障。
