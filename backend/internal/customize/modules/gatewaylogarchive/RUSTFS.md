# RustFS 主归档与按桶转存

## 配置

1. 多节点部署先将所有网关更新到支持此功能的版本。数据库迁移会给既有桶设置「目标存储桶」和「跟随采集配置」，保持原优先级行为。确认各节点使用独立持久化数据卷、同一数据库，并均能访问 RustFS 和目标桶，再启用新用途和桶级策略。
2. 在「网关日志存储 → 存储桶」新增一项，用途选 **RustFS 主归档**，填写实际 S3 API 地址（如 `http://rustfs:9000`）、已创建的私有 Bucket、Region、前缀和凭证。该地址必须能从每个网关容器访问。默认勾选 Path-Style；使用「测试连接」检查写、Range 读、删。主桶还需支持 S3 分片写入、完成和取消。一次只能启用一个主归档。
3. 如果要同时输出未脱敏和脱敏两种副本，把受信任的 RustFS 主桶设为 **保留原文**。对每个启用的目标桶分别选「上传时脱敏」「保留原文」或「跟随采集配置」。如果要求 RustFS 本身只存脱敏数据，可以把主桶也设为脱敏；这种主归档不能再提供原文，要求原文的转存任务会显示错误。不会用本地原始日志绕过主桶设置。
4. 点击「归档文件 → 转存状态」可查看每个目标桶的完成状态及最近错误。失败副本单独退避重试；停用目标桶可暂停该桶转存，重新启用后继续。目标集合在主文件上传成功时记录，之后新增的桶不自动回填历史。每次真正写入副本时读取目标桶策略，已上传文件不跟随配置变化。已有暂存或转存引用时，请停用桶而不是删除或改指另一个地址。

## 数据和占用

`本地活动会话 → RustFS 暂存片段 → RustFS 大 JSONL → 后台从 RustFS 读取 → 各目标桶`

- 请求不等待对象存储。活动会话使用原有的本地 `spool/` 做崩溃恢复；会话结束后后台将其直接流式写入 RustFS。正常情况下节点不保存一整份待上传大 JSONL。一个目标对应一份完整未压缩 JSONL；不同策略可产生不同文件大小。
- 标准 S3 对象不能反复追加。后台在专用前缀 `_gateway-staging/` 写入短期片段，到容量上限、跨日或手动结束写入时，通过流式读取、校验和分片上传组装主 JSONL。主对象和索引确认后清理远端片段。合并时 RustFS 需为片段和正在生成的主文件预留空间；1 TB 是总容量，建议保留默认 10 GB 的单文件上限，并监控剩余容量。不要对尚在使用的暂存片段设置短期强制过期。
- RustFS 写失败（含断网、满盘）后，当前会话回退到所属节点的 `fallback/`。两边都写不成功则保留源 spool 重试。后台每次失败后等待约 30 秒再发起读写探测；恢复后主动封存含有回退文件的归档并补传，不用等新会话。已仅存于 RustFS 的片段在其故障期间等待读取。默认成功后清除本地回退文件，配置了本地保留期则按期清理。本地空间阈值对活动 spool 和故障回退仍然有效。
- 最终主对象保留在 RustFS。索引和统计更新后生成独立、持久化的副本任务。后台网关进程用数据库租约认领，可由其他节点接续；数据经网关进行流式传输、校验和按桶脱敏，网关与 RustFS 之间会产生读流量。这不是 RustFS 服务端原生复制。上传统计按实际写入各桶的文件/大小累计，包含副本。后台的会话预览、原文件下载和跨节点导出读取主对象。
- RustFS 最终归档没有容量驱逐策略。不要在下游任务完成或后台仍需预览时提前删除主对象。主桶若启用了 S3 版本控制，要通过 RustFS 生命周期管理旧版本（删除暂存对象可能只生成删除标记）和未完成的分片上传。各目标最好使用本应用专用前缀。
