# RustFS 主归档与按桶转存

## 配置

1. 多节点部署先将所有网关更新到支持此功能的版本。数据库迁移会给既有桶设置「目标存储桶」和「跟随采集配置」，保持原优先级行为。确认各节点使用独立持久化数据卷、同一数据库，并均能访问 RustFS 和目标桶，再启用新用途和桶级策略。
2. 在「网关日志存储 → 存储桶」新增一项，用途选 **RustFS 主归档**，填写实际 S3 API 地址（如 `http://rustfs:9000`）、已创建的私有 Bucket、Region、前缀和凭证。该地址必须能从每个网关容器访问。默认勾选 Path-Style；使用「测试连接」检查写、Range 读、删。主桶还需支持 S3 分片写入、完成和取消。一次只能启用一个主归档。
3. 如果要同时输出未脱敏和脱敏两种副本，把受信任的 RustFS 主桶设为 **保留原文**。对每个启用的目标桶分别选「上传时脱敏」「保留原文」或「跟随采集配置」。如果要求 RustFS 本身只存脱敏数据，可以把主桶也设为脱敏；这种主归档不能再提供原文，要求原文的转存任务会显示错误。不会用本地原始日志绕过主桶设置。
4. 点击「归档文件 → 转存状态」可查看每个目标桶的完成状态及最近错误。失败副本单独退避重试；停用目标桶可暂停该桶转存，重新启用后继续。目标集合在主文件上传成功时记录，之后新增的桶不自动回填历史。每次真正写入副本时读取目标桶策略，已上传文件不跟随配置变化。已有暂存或转存引用时，请停用桶而不是删除或改指另一个地址。

## 本地旧归档停在 0 B，或某个节点一直提示回退

- **本地 JSONL → 主桶**：页面分别显示网络传输层已读取的请求体字节（含重传）和存储桶已确认的字节。前者增加不等于 RustFS 已持久化；进度条只计后者。对于 18.35 GiB 的原件，每片 16 MiB，最多并行两片，最后在桶中合成一个对象，不另写 `.upload-tmp`。创建分片任务最多等 1 分钟；单片连续 2 分钟无发送进展且无确认才中止本次尝试。使用同一上传 ID、片号和内容重传，遇到无响应或 HTTP/2 协议错误可用 HTTP/1.1 重试。持续发送时不限制整个文件的上传时长。合并最多等 5 分钟；本次任务失败会保留源文件并退避重排，整个任务重排或进程重启会重新开始上传。
- **会话 → RustFS 暂存片段**：不再把转换和所有分片共用一个 2 分钟期限。写入失败后，这台节点暂存本地；独立后台任务在约 30 秒后开始探测，即使本节点还有其他归档正在上传也能检测恢复。恢复探测会实际写入一个很小的测试对象，验证分片写入与合并、Range 读取、删除。通过后封存含本地回退数据的归档，加入补传队列。单次小对象探测通过不代表大流量链路一定畅通。
- **升级旧节点**：逐台升级网关，保留各自原有 `/app/data` 挂载、`gateway-log-archive/node-id` 和共享数据库。节点启动会重新领取它上次处于「上传中」的本地归档，无需改数据库、删原件或重复点击「立即结束写入」。先看页面「当前节点」，再看 A 的上传阶段、已确认字节，或 B 的黄色回退提示和上次探测的时间、失败步骤。「最近错误」是历史记录。未成功前不要清理本地原件、`spool/` 或 `fallback/`。若仍超时，将具体操作（建任务、写片或合并）与该节点至 RustFS 链路上的 S3/反代日志对应；HTTP `403` 查对应操作的权限，`413` 查代理的单次请求体上限。

- **读错误文本**：页面中的存储桶错误写成「S3 操作 + 结果（已尝试次数）：原因（方法 地址）」。「请求未送达或无响应」表示没有拿到 HTTP 响应，原因部分区分 `connection refused`（RustFS 未监听或正在重启）、`no such host`（容器网络或 DNS）、`i/o timeout`（防火墙或链路）、`EOF` / `connection reset`（RustFS 或代理断开连接）。「请求被中止：context deadline exceeded」只出现在 `v0.2.23-4` 之前的版本：旧版给一次会话的转换和全部分片共用 2 分钟期限。旧记录仍是 SDK 原文，页面会保留首尾两段，完整内容看悬停提示。

可用本地 HTTPS 模拟 S3 对实物大小做回归：在 `backend` 目录设置 `GATEWAY_LOG_ARCHIVE_TEST_18GIB=1`，运行 `go test -tags=integration -count=1 -timeout=12m -run '^TestLocalArchive18GiB$' -v ./internal/customize/modules/gatewaylogarchive`。测试的临时目录需至少 19 GiB 可用空间，生成一份 18.35 GiB 测试文件，接收端流式校验 1,175 个分片的 SHA-256 和顺序，不使用生产凭证或生产数据。

## 多个文件都显示「默认存储桶：重试中 PROTOCOL_ERROR」

文件旁的 `s3://…` 是主归档的位置。下方的「重试中」表示该目标桶上一次转存失败，任务可能正等待重试。`stream ID` 是 HTTP/2 的流编号。旧的错误文本没有区分从主桶读取、向目标桶写入，或是哪一端的代理中断了传输。存储桶「测试连接」只验证小对象操作，测试成功不能排除大文件传输中断。

以页面显示的 57.85 MB、257.06 MB、628.19 MB 为例，这些大小对应的目标上传分片都是 16 MiB。按原文大小分别是 4、17、40 个分片；目标桶脱敏后分片数取决于转换后的实际大小。旧版本（含 `v0.2.23-2`）对 RustFS 的一次 GET 从头读到文件尾。较大文件让这条流保持打开更久，也需要更多次目标写入；仅凭这组大小不能推断代理或存储桶设了 256 MB 上限。

升级所有网关节点后，后台会接续数据库里已有的任务，包括旧版留下的 `stream error: stream ID …; PROTOCOL_ERROR; received from peer`。源 JSONL 每次最多读取 32 MiB，同一次转存遇到断流时从下一个未读取的字节续读（每段最多重试两次），保留逐行校验和目标桶脱敏。若目标端在分片写入时报告该 HTTP/2 错误，后续分片重试可改用 HTTP/1.1，沿用同一上传 ID 和分片编号，即使确认响应丢失也无需重传前面的分片。HTTPS 仍校验证书。分片重试耗尽或进程重启时，整次任务仍须重新开始。不会在网关磁盘生成第二份 JSONL。

目标桶保持启用即可；首次失败后约 1 分钟重试，随后逐步延长至最多 1 小时。无需重建任务、重新采集或删除主对象。成功后重新点击「转存状态」可看到「转存完成」。若仍失败，「读取主桶 … 字节 …」对应 RustFS 的 Range GET 和它前面的代理；「写入目标桶 …」对应目的桶的 S3 写入请求。可按错误时间对照两端日志，不必更改正常网关请求的 HTTP 配置。

在 `backend` 目录运行 `go test -tags=integration -run '^TestRelayLargeJSONL$' -count=1 -v ./internal/customize/modules/gatewaylogarchive`，可用本地 HTTPS 模拟存储桶验证这三种大小、读取中断和分片确认丢失；测试校验目标文件 SHA-256，不需要生产凭证。

该测试默认跳过 10 GiB 用例。要验证后台默认的 10 GB 上限，可在当前终端设置 `GATEWAY_LOG_ARCHIVE_TEST_10GIB=1`，运行 `go test -tags=integration -run '^TestRelayLargeJSONL$/^10GiB$' -count=1 -timeout=12m -v ./internal/customize/modules/gatewaylogarchive`。它在本机逐行生成并实际转存 10 GiB，保持脱敏前后等长，在距文件尾约 40 MiB 处中断读取，并模拟第 639 片已写入、确认响应丢失。通过条件是保留之前成功的分片，640 片只完成一次合并，目标 10 GiB 内容与预期脱敏结果的 SHA-256 一致。

## 数据和占用

`本地活动会话 → RustFS 暂存片段 → RustFS 大 JSONL → 后台从 RustFS 读取 → 各目标桶`

- 请求不等待对象存储。活动会话使用原有的本地 `spool/` 做崩溃恢复；会话结束后后台将其直接流式写入 RustFS。正常情况下节点不保存一整份待上传大 JSONL。一个目标对应一份完整未压缩 JSONL；不同策略可产生不同文件大小。
- 标准 S3 对象不能反复追加。后台在专用前缀 `_gateway-staging/` 写入短期片段，到容量上限、跨日或手动结束写入时，通过流式读取、校验和分片上传组装主 JSONL。主对象和索引确认后清理远端片段。合并时 RustFS 需为片段和正在生成的主文件预留空间；1 TB 是总容量，建议保留默认 10 GB 的单文件上限，并监控剩余容量。不要对尚在使用的暂存片段设置短期强制过期。
- RustFS 写失败（含断网、满盘）后，当前会话回退到所属节点的 `fallback/`。两边都写不成功则保留源 spool 重试。后台每次失败后等待约 30 秒再发起读写探测；恢复后主动封存含有回退文件的归档并补传，不用等新会话。已仅存于 RustFS 的片段在其故障期间等待读取。默认成功后清除本地回退文件，配置了本地保留期则按期清理。本地空间阈值对活动 spool 和故障回退仍然有效。
- 最终主对象保留在 RustFS。索引和统计更新后生成独立、持久化的副本任务。后台网关进程用数据库租约认领，可由其他节点接续；数据经网关进行流式传输、校验和按桶脱敏，网关与 RustFS 之间会产生读流量。这不是 RustFS 服务端原生复制。上传统计按实际写入各桶的文件/大小累计，包含副本。后台的会话预览、原文件下载和跨节点导出读取主对象。
- RustFS 最终归档没有容量驱逐策略。不要在下游任务完成或后台仍需预览时提前删除主对象。主桶若启用了 S3 版本控制，要通过 RustFS 生命周期管理旧版本（删除暂存对象可能只生成删除标记）和未完成的分片上传。各目标最好使用本应用专用前缀。
