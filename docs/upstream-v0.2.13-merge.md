## 重叠功能的处理

| 范围 | 合并规则 |
| --- | --- |
| 充值阶梯赠金/折扣 | 上游配置优先。只要配置了原生阶梯，本地自动充值活动不覆盖报价（包括低于第一档的金额）；旧页面带活动 ID 下单时拒绝并要求刷新。没有原生阶梯时继续支持二开活动。 |
| 历史支付订单 | 不用当前活动开关或新阶梯重算历史订单；继续使用落库金额、赠金、优惠券与活动快照，保留履约、退款、邀请奖励冲回路径。 |
| 优惠券 | 独立功能保留，按原生报价的实付基数再减券，保持到账及上游 `bonus_amount`；订单和优惠券占用同事务提交。 |
| 图片模型识别 | 上游原生 Responses 分类不扩张。Gemini 走上游 API-key-only Images 兼容入口；本地 NanoBanana 别名、Gitee Z-Image 通过相同兼容边界保留，不能误入 OAuth/SetupToken 原生转码。 |
| 模型广场/计价 | 上游分组模型定价、推理强度策略优先；保留没有原生模型定价覆盖时的二开视频分辨率报价。 |
| 账号与平台 | 接入 TypeSafe/OpenCode 管理态及上游字段，保留账号上游分组、排序、探测间隔和授权约束。插件账号快照新增字段显式分类，凭据与循环关系仍剥离。 |
| API Key | 上游分组排序与筛选保留；二开次级分组检索使用 Ent 方言感知 JSON 条件，避免 SQLite 测试与 PostgreSQL 语法冲突。 |
| 发布 | 保留上游 prepare/矩阵/源码绑定/产物校验流程，并接入 canvas 产物和 agent。二开任务 checkout 同一个 prepare SHA，dry-run 不发布 npm 包。 |

上游新增的公开订单校验限流、邮箱令牌原子操作、已删除 API Key 的使用结算、Antigravity 文档/错误处理等改动随完整 merge 接入，不以二开功能开关阻断原生能力。
